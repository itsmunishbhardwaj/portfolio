Before → After

Before: Static-secret sprawl

10+ services authenticating with long-lived static secrets to PostgreSQL and Blob Storage.

Every audit flags the same finding: secrets that can leak, expire silently, or need manual rotation.

After: Passwordless by design

Every connected service — Keycloak, AppStore, AIEM, Telemetry, MLOps, Authz, Drive, Securestore, Feature Store, H2O GPTe — authenticates via short-lived federated tokens.

Zero secrets to rotate, leak, or explain to an auditor.

The Problem

A credential failure waiting to happen

10+Services needing federated auth, none passwordless yet
2Recurring Azure AD errors blocking every attempt (AADSTS700211, AADSTS700213)
~7 wksOf cascading credential failures before the first working token
24Federated credentials ultimately required, by design not guesswork

"I might have found an alternative to make this work. We can register an app to create a service principal." — opening the investigation in #proj-workload-identity before the first working attempt existed

The Solution

Terraform-authored identity, automated from the start

  • Terraform-authored identity, not console clicks — 13 managed identities and 24 federated credentials as reusable for_each loops, not one-off setup. Repeatable next environment.
  • Automation for the boring part — check-and-create-federated-credentials.sh creates credentials across 11 namespaces in one run. Minutes, not a checklist.
  • A separate audit script to verify credential status independent of the creation script. Trust but verify.
  • Passwordless database and storage auth for every connected service via Azure AD tokens. The actual deliverable.
If a human has to rotate it, it's a future incident. Automate the credential, not just the fix.

Key Learnings
1

Debug the abstraction, not the symptom.

AADSTS700211 and AADSTS700213 look like config typos; they're actually issuer/subject-trust mismatches. Fixing the symptom (re-entering values) doesn't work — you have to understand the federation model itself.

2

Automate the fix, not just the incident.

Solving it once for one service would have been a support ticket. Building the script that does it for any namespace turned a fix into infrastructure.

3

Security work needs a receipt.

The separate audit script wasn't asked for — it was built because "trust me it's configured" doesn't survive a compliance review.
