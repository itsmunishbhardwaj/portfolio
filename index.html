Gauge Live · deployed

An assessment engine that diagnoses the type of understanding gap, not a score. Three scoring axes grounded in learning-science research rather than invented at the prompt. The design decision that matters: classification was taken away from the model — headline scores and gap type are computed deterministically in Python from locked thresholds, and the LLM only writes the narrative around a verdict the code has already fixed. Six calls split across two models by job. A JSON-repair layer that strips fences and retries, because malformed JSON from a free tier is an incident, not a quirk.

Result: 1,652 lines of Python behind 8 REST endpoints, live on Render, built and deployed in one hackathon cycle inside a documented free-tier budget.

LLM test report generator Shipped at H2O.ai

Merged into the CI pipeline as a reusable GitHub Actions workflow. JUnit XML tells you what failed but never what happened. This parses the XML, sends structured test data to H2OGPTE, and renders a standalone HTML report with a PASS / CONDITIONAL PASS / FAIL verdict and a root-cause classification per failure — product bug, infrastructure, flaky, or config.

The part that matters here: every LLM-generated claim is threaded back to real evidence — the CI run URL, the source XML file and the specific test name are carried in the prompt context and rendered in the output, so the narrative stays grounded rather than plausible. Graceful fallback to a data-only report when the model is unavailable. 773 lines, any pipeline can call it.

Internal repository — not linkable, but happy to walk through the design and the merged pull request in a conversation.

Needle Running daily

A mobile agent that turns photos, voice notes and screenshots into a weekly plan written straight into my calendar. Built first as a Gemini Gem; calendar writes failed silently, so it was migrated wholesale to a Claude Project with first-party Drive and Calendar connectors — the framework survived the move because the logic lived in the prompt design, not the vendor. Google Drive is the state store: five templated files the agent reads and writes, including a learnings file updated on weekly review so prioritisation adapts instead of resetting.

The design choice you'll recognise: listen-only is the default. Most input is captured and routed silently; the agent acts only on one of seven explicit commands. Recommend-first, arrived at by watching a tool call fail rather than by reading a best-practice post.

Second Brain In use

A wiki an LLM maintains — the personal version of an organizational memory layer. Karpathy's LLM-Wiki pattern crossed with an Obsidian structure of sources, entities, concepts, analyses and comparisons, so the output stays navigable by a human and not just by the agent. The operating contract is explicit: raw sources immutable, three named workflows, mandatory index and log updates after every action.

The rule that makes it work: an answer is filed as a page, not returned as chat — the difference between a knowledge base that compounds and a chat history that doesn't. Ingested a 15-source certification corpus into 8 structured domain files and 9 concept syntheses.

Becoming In build · daily use

A goal system built on the observation that every tracker flattens life into one list of checkboxes, when the things being tracked behave differently — finite projects that end, timestamped activities with effort, and binary daily habits. Goals are modelled as a graph with three deliberately distinct child types, so a single log ("gym, 55 minutes") resolves upward to a project and a goal without manual tagging while also satisfying a habit.

Result: 8,141 lines across 9 screens and 11 components, covered by 24 test files. 103 commits, PRs numbered to #25, shipped as an installable PWA and in daily use. Not an LLM product — a data-modelling and testing one, and it's on this page because tests written alongside the model is the habit, not the exception.
