The Outage That Became a Runbook

A full-cluster outage, root-caused, fixed across 9 namespaces, and turned into a script so it can't happen the same way twice.

Before → After

Before: Silent expiration, full outage

A Docker PAT token expired with no warning; every pod needing a fresh image pull started failing.

33+ pods in ImagePullBackOff across the entire client environment.

After: Scripted recovery, documented root cause

fix_docker_credentials.sh rotates the credential and force-restarts affected pods across every namespace in one run.

A written investigation report so the next engineer doesn't re-diagnose from zero.

The Problem

One shared secret. Every namespace down.

33+Pods down simultaneously, ImagePullBackOff across every namespace
9Namespaces affected by one expired secret
1Shared registry secret (h2oai-registry) — a single point of failure for the whole environment
0Warning before the token expired — it just stopped working
The Solution

Fix it live. Then make the fix a script.

  • Root-caused to the actual failure, not the symptom — traced ImagePullBackOff back to an expired Docker PAT in the shared registry secret, not a Kubernetes scheduling issue.
  • Fixed it live — updated credentials across all 9 affected namespaces and force-restarted every impacted pod.
  • Then didn't stop there — built fix_docker_credentials.sh so the same fix is a script next time, not a live investigation. One command, any namespace.
  • Wrote the investigation report — root cause, blast radius, and fix, documented while it was fresh.
A fix that isn't automated is a promise to debug the same thing again.
The Impact
9/9Namespaces recovered

Key Learnings
1

A single shared secret is a single point of failure, full stop.

The outage wasn't really a Docker problem — it was an architecture problem (one secret, every namespace depends on it) that happened to surface as a Docker problem.

2

The fix isn't done until it's reusable.

Restoring service ends the incident. Writing the script ends the next incident before it starts.

3

Document while it's fresh, not after.

The investigation report was written during recovery, not weeks later from memory — that's the difference between an accurate root cause and a guess.
